## 9. Incident registry — pattern "config changes detonate latent code bugs"

> Named pattern: **config changes detonate latent code bugs.** A latent defect sits dormant while its triggering condition is absent; an unrelated config change supplies the condition and the defect fires in production. Prevention = any change to a dependency's presence/credentials/topology must exercise the *consumer's* runtime path, not just the boot path.

**INC-001 (2026-10-14) — Redis AUTH outage, whole site 500.**
- **Timestamp**: 20:26–20:48 UTC 2026-10-14 (detected on deploy `38631585014`, resolved by `38634666111` @20:48).
- **Root cause**: `security.py`'s boot probe used bare `socket.create_connection()` (proves port open only). Deploy `0c59f706` wrote a passwordless `REDIS_URL` while the box's apt Redis had `requirepass` → Redis answered TCP (probe "healthy") but rejected every command with `NOAUTH` → flask-limiter's client threw on **every request**; `AuthenticationError` subclasses `ConnectionError`, so the probe couldn't distinguish healthy-vs-rejecting and returned the real URL. Config change (Brevo `.env` write) detonated the latent bare-TCP probe bug.
- **Impact**: every route 500 for ~22 min; CI caught it at the localhost USD-pricing gate in seconds (no auto-recovery, only detection).
- **Fix** (`96cce432`): probe now uses `redis.Redis.from_url(...).ping()` — the same client flask-limiter uses; reaching PING proves usable, anything else → `memory://` + warning. `init_security` additionally wraps `Limiter(...)` in try/except → `_NoopLimiter`, and the probe-failure branch now logs `RATE_LIMITER_OFF:` at **error** level when `IS_PRODUCTION` (loud, not a droppable warning).
- **Prevention**: (1) real `ping()` probe = client-parity, never TCP; (2) `_NoopLimiter` fail-safe so limiter setup can never take the site down; (3) `RATE_LIMITER_OFF` error log = this state can never ship silently again. **Redis AUTH fix shipped** (deploy.yml, session 2): INC-001 auth-alignment block — detects NOAUTH → classifies bind (loopback-only guard, fail-safe keep-auth otherwise) → tries known credentials (`requirepass` conf / `REDIS_PASSWORD` env / `changeme`) and, if one authenticates, carries it in `REDIS_URL` (no restart); else drops `requirepass` at the source + restart (before the app restart, so no request sees the blip) → verifies PONG. Plus a post-restart CI gate greps the journal for `RATE_LIMITER_OFF` and fails the run summary loudly (`::error::`) — non-fatal but impossible to miss. Verified locally: 5-scenario fake-redis harness (candidate-auth / restart-fix / non-loopback / healthy / dead) + sed-regex scrub proof + IPv6-loopback classification + hostile-password URL encoding. **Verified post-deploy (CI `38760438479`, 15:29Z 2026-10-15)**: box path taken = NOAUTH → loopback `127.0.0.1:6379` → no candidate password matched → sed+restart → `Redis now answers PONG (passwordless, loopback-only)`; gate `OK: no RATE_LIMITER_OFF since restart (shared limiter active)`; live probe **14× → 10×200 + 4×429**, second burst **12×429 `RATE_LIMITED`** = shared global counter ON. **P0 #5 CLOSED.**

**DEC-001 (2026-10-15, decision not incident) — register auto-verifies accounts when verification email can't send.**
